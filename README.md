# Тестирование API с Rest-Assured, JSON Schema и оркестрация SUT в GitHub Actions

Инфраструктурный учебный проект, полностью сфокусированный на настройке CI/CD-конвейера для интеграционного тестирования API, автоматизации запуска тестируемой системы (SUT) в фоновом режиме средствами Bash и валидации структуры ответов сервера по строгим схемам.

## 🎯 Цели и задачи проекта
* **Оркестрация окружения в CI**: настройка пайплайна в **GitHub Actions**, способного автоматически разворачивать бинарный артефакт тестируемого сервиса (`.jar`) в фоновом режиме перед стартом тестовой сессии.
* **Управление артефактами в Git**: практика принудительного индексирования бинарных файлов, заблокированных глобальным `.gitignore`, для передачи их в удаленный репозиторий.
* **Валидация контрактов (Contract Testing)**: интеграция библиотеки **Rest-Assured** и настройка валидатора `json-schema-validator` для проверки структуры JSON-ответов на соответствие эталонной схеме.
* **Анализ отказоустойчивости CI**: демонстрация воспроизводимости падений сборки в CI при обнаружении несоответствий контрактов (валидация логики падения билда).

## 🛠️ Архитектура и развертывание окружения

Тестируемая система (SUT) поставляется в виде скомпилированного Java-артефакта `app-mbank.jar`.

### 1. Локальный запуск сервиса
Для ручной верификации и отправки запросов сервис разворачивается локально из корневой директории проекта через терминал:
```bash
java -jar ./artifacts/app-mbank.jar
```

### 2. Принудительное версионирование в Git
Поскольку расширения `.jar` по умолчанию занесены в черный список `.gitignore`, в данном проекте отслеживание артефакта было активировано принудительно:
```bash
git add -f artifacts/app-mbank.jar
```

### 3. Фоновый запуск в GitHub Actions (Bash)
В конфигурационном файле CI-конвейера настроен шаг, запускающий `app-mbank.jar` в фоне с помощью Bash-операторов (например, с использованием `&`), что позволяет тестам выполнять HTTP-запросы к развернутому веб-серверу на том же инстансе.

## 🧪 Валидация контрактов по JSON-схеме

В проекте используется декларативный подход к проверке структуры API-ответов. Эталонная схема `accounts.schema.json` размещена в каталоге тестовых ресурсов (`src/test/resources/`).

### Реализация в автотестах:
В тестовом классе реализован статический импорт метода валидации и проверка структуры:
```java
import static io.restassured.module.jsv.JsonSchemaValidator.matchesJsonSchemaInClasspath;

// Фрагмент кода автотеста
.then()
    .statusCode(200)
    .body(matchesJsonSchemaInClasspath("accounts.schema.json"));
```

### Модификация и усложнение схемы:
В соответствии с требованиями, JSON-схема была доработана ограничениями на тип данных `object`. Были внедрены правила валидации валютных полей, разрешающие строго два типа значений: **«RUB»** или **«USD»**.

## 🔄 Жизненный цикл тестов и история сборок в CI

Для подтверждения качества настройки конвейера в истории сборки GitHub Actions зафиксированы оба возможных исхода выполнения пайплайна:

1. ❌ **Сборка со статусом FAIL**: 
   * Моделировалось путем искусственного искажения схемы (изменение валидного значения валюты с `RUB` на `RUR` или подмена типа данных идентификатора `id`). Тесты Rest-Assured мгновенно зафиксировали нарушение контракта, завершив сборку ошибкой.
2.  **Сборка со статусом SUCCESS**:
   * Финальный коммит с корректными настройками схемы и кодом тестов успешно проходит все этапы конвейера.
